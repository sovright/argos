## Resulting behavior

A reviewed sweep consumes its one-shot proposal ID, checks height-sensitive scan state, syncs wallet-backed routes, and builds every ordered leg before the first signer or submitter. The final preflight compares the complete public quote and typed, canonical source identities. Each signer consumes the already validated backend proposal or exact standalone UTXO slice and the fee bound to its own typed leg. A same-ZIP317-fee note/outpoint/amount change, a changed later account, or mixed direct/HD legs sharing a display account cannot silently alter the signed plan. The CLI transparent wallet-file path has an opaque reviewed quote, displays gross/fee/net, defaults an omitted fee cap to that quote, and verifies the live input/target plan again before signing.

Durable broadcast history and the cross-process workspace-operation lock now live under one registry for each canonical data directory and network, outside scan-parameter-dependent workspaces. Scan, quote, sweep, reconciliation, CLI transparent signing, and deletion use this operation boundary. Existing workspace and CLI transparent journals are discovered and imported with exact-byte source/prefix checks; migration failure stops a fresh operation. Historical `Pending` (including Accepted), `SubmissionUnknown`, and `NotSubmitted` remain blocking after restart. Every post-network-I/O nonaccept response remains Unknown and fee-at-risk, even if an untrusted server presents it as a deterministic rejection. Legacy retryable Pending replays without authorizing a new such transition; legacy post-I/O Rejected replays conservatively as Unknown. A rejected new transition does not append any bytes.

The GUI and CLI can observe durable transactions through configured confirmation authorities after restart. An explicit Unknown or NotSubmitted retry submits only the stored raw transaction and requires a selected txid; the GUI also requires typing the full txid after explaining that the network/data-dir registry may include another recovery. Observation or retry that changes any durable state invalidates the old handle's reviewed quotes, even when a later observation errors or a retry becomes ineligible. A fresh scan and review are required. Two independent operator-labelled confirmation sources can be configured in the GUI and are passed into all scan and reconciliation paths; no second operator is invented by default. Presence without canonical mining can establish Pending, while absence/unavailability/contestation cannot turn Unknown into Pending. Loss of canonical Mined evidence downgrades finality; operator IDs are case-folded before independence is counted. Confirmation polling returns the final persisted state rather than assuming Pending after its last attempt.

Deletion refuses an active same-workspace operation and takes the stable cross-process operation lock before reading history or removing files. It checks the actual surviving path again on a cleanup retry, including its journal, current outcome, and balances. Durable cleanup markers and tombstone discovery prevent a restart from opening a fresh workspace while an old journal remains stranded. Deletion requires an actual eligible sweep result whose nonempty txid set matches mined durable receipts, no error/skips/follow-up, no unresolved history, and fresh independent canonical mining evidence for every durable Mined receipt. Standalone transparent keys require two independent fresh zero-UTXO reports; shielded workspaces cannot be deleted until an independent complete shielded rescan can verify zero. The lock sidecar and global registry survive workspace removal. The Tauri delete command forwards to this guarded service.

## Design rulings and consequences

- **Ruling:** Bind the full ordered public quote, typed leg identity, exact source set, and each leg's own fee after sync and before signing; consume the validated proposal/UTXO snapshot. **Consequence:** equal-fee source swaps and late-leg changes require a new review before any route submits. Mixed direct and HD legs with the same display account cannot borrow one another's fee.
- **Ruling:** Give standalone CLI transparent recovery an opaque reviewed quote with a default cap equal to its exact fee. **Consequence:** omitted `--max-fee` cannot silently authorize an unreviewed fee, and a changed outpoint/target plan stops before submission.
- **Ruling:** Scope the broadcast registry and operation lock to canonical `(data_dir, network)`, regardless of birthday, scan range, key order, or authority subset. **Consequence:** aliases cannot bypass unresolved history; unrelated wallets in one data directory/network may conservatively block each other. A different data directory is an explicit residual coordination boundary.
- **Ruling:** Import legacy workspace/transparent logs under that lock with immutable source digests, exact event-prefix checks, and crash-gap recovery. **Consequence:** an old Unknown cannot be orphaned by changing scope or moving a workspace; changed/conflicting legacy sources stop operations rather than being silently skipped.
- **Ruling:** Hold the global operation lock throughout scan/sweep and deletion, plus a same-root in-process gate. **Consequence:** a second process/service cannot remove the wallet DB while another process scans or signs; deletion refuses active work instead of waiting into a deleted session.
- **Ruling:** Use a durable cleanup marker and restore/inspect the actual tombstone or root on retry. **Consequence:** a failed rename/removal remains retryable after restart, while newly appended Unknown history or arriving funds prevents the retry from deleting keys.
- **Ruling:** Require durable outcome/txid coherence, freshly re-observed canonical Mined evidence, and independent zero-balance evidence for destructive cleanup. **Consequence:** GUI-only mined results, stale finality, partial/skipped outcomes, or a hostile primary hiding transparent funds cannot authorize deletion. Shielded cleanup fails closed until independent complete zero verification exists.
- **Ruling:** Keep every historical Pending and Unknown blocking; allow old schema-v1 retryable/no-presence Pending only during replay and prevalidate new events before append. **Consequence:** old logs remain readable and block fresh bytes; invalid new transitions neither gain certainty nor poison the JSONL file.
- **Ruling:** Treat every post-I/O nonaccept response as SubmissionUnknown, including deterministic-looking rejection and duplicate responses, and reinterpret legacy post-I/O Rejected as Unknown. **Consequence:** the reviewed aggregate fee stays at risk and later legs stop; only stored bytes can be explicitly retried after observation. New terminal Rejected appends are refused without provable local pre-I/O provenance.
- **Ruling:** Promote Unknown to Pending only on acceptance or positive transaction presence, never on Absent/Unavailable/Contested/Reorged or retryable rejection; retain the actual durable state after polling. **Consequence:** unexpired absent Unknown remains exact-byte eligible, and the outcome cannot report stronger certainty than the journal.
- **Ruling:** Demote Mined when fresh canonical evidence is lost, including PresentUnmined or Unavailable, and compare explicit operator labels case-insensitively. **Consequence:** a reorged-to-mempool tx or capitalization alias cannot justify follow-up execution, expiry, or deletion.
- **Ruling:** Make observe-only reconciliation reachable from normal GUI and persistent CLI flows, and permit explicit exact-byte retry from Unknown or crash-before-I/O NotSubmitted. **Consequence:** a late-mined Pending can clear after restart; no caller can supply replacement bytes to the retry route.
- **Ruling:** Any durable state change revokes old reviewed intent and requires a fresh scan, including partial observer errors and an ineligible retry that first discovers mining. **Consequence:** a previously quoted input set cannot be reused after reconciliation mutates one historical record.
- **Ruling:** Allow cross-wallet history visibility within the global registry but require deliberate full-txid confirmation for GUI retry; CLI retry requires `--txid --resubmit`. **Consequence:** legacy records need no guessed owner metadata, while a user must explicitly select the exact transaction to resend.
- **Ruling:** Require independently operator-labelled confirmation endpoints in the GUI and pass them through every scan/reconciliation constructor. **Consequence:** two-source canonical mining is attainable in the shipped UI when configured, and missing independent sources delay finality and cleanup clearly.
- **Ruling:** Narrow unreviewed imported/transparent signing entrypoints and keep Tauri deletion as a service call. **Consequence:** product callers use reviewed quote authority and cannot bypass backend cleanup checks through a GUI result.

## RED to GREEN evidence

The first security-fix commit covered focused failures for same-fee direct outpoint/shielded note swaps, changed later-leg amount, post-sync quote/authority change, direct target height, mixed ordering and typed leg identity, accepted Pending reopen, no-presence Unknown downgrade, rejected append byte preservation, concurrent deletion, external lock, partial-removal retry, and the public fake-lightwalletd transparent proposal/outpoint-swap path. The rereview then added and corrected these focused failures:

- A raw schema-v1 `Prepared -> SubmissionUnknown -> Pending` retryable event chain initially failed to reopen; replay now accepts it while a new retryable Pending write remains refused. A raw legacy post-I/O Rejected fixture now reopens as blocking Unknown with its original bytes/disposition.
- A hostile submitter that captures raw bytes and returns deterministic-looking refusal initially yielded Rejected and permitted follow-up; it now yields Unknown, preserves exact raw/txid, and stops later routes with the fee at risk.
- Mined followed by PresentUnmined, Unavailable, or reorg evidence could retain stale finality; durable observation now demotes it. Capitalization-only operator aliases no longer provide independent Mined or Expired evidence. An exhausted Unknown confirmation poll now reports the persisted Unknown.
- A restored deletion root with new Unknown or newly arrived transparent value, an orphaned tombstone after restart, a second service scanning concurrently, a changed legacy log, and a hostile primary reporting zero against a funded secondary each initially exposed cleanup/alias gaps; all now refuse destructive cleanup or fresh signing. The true two-service active-scan test exercises the production lock, not merely a manually held journal lock.
- A mixed direct/HD route sharing a display account initially selected the direct fee for HD; typed fee assertions now preserve each exact fee. A CLI transparent quote with omitted cap and an equal-fee outpoint swap initially could sign the changed plan; the opaque quote path refuses it with zero captured submissions.
- Accepted Pending after reopen initially stranded follow-up flows; GUI/CLI observe-only reconciliation now exposes late mining and a new review path. Explicit Unknown/NotSubmitted retry uses only durable bytes. A partial two-record reconciliation error and a retry that observed mining initially left an old review usable; both now invalidate it and require a fresh scan. GUI cross-wallet retry requires typed full txid.
- A changed birthday/scan scope, reordered imported keys, and CLI `[A]` versus `[A,B]` source subset initially reached separate logs; the network registry imports/blocks those aliases. Crash-between-import-and-manifest checks accept only an exact event prefix and refuse mutated sources.
